# Titanic MLflow Pipeline

An incremental machine learning pipeline built on the Titanic dataset.  
The dataset is split into two parts. The pipeline trains on each part separately,
logging every run to MLflow — and accumulates predictions across all runs into a
single growing CSV.

---

## What I Built

### The Problem I Was Solving

I wanted to simulate a real-world scenario where data arrives in batches (not all
at once). Each time a new batch arrives, the pipeline should:

- Train a fresh model on that batch
- Track the run in MLflow (params, metrics, model artifact)
- Remember which batches have already been processed so it never double-trains
- Build up a cumulative record of every prediction ever made

### How I Split the Data

The original `titanic.csv` was split into two files:

| File | Description |
|------|-------------|
| `part1.csv` | First batch — used to build and validate the initial pipeline |
| `part2.csv` | Second batch — added later to test that the pipeline picks it up automatically |

## How It Works

### `run_pipeline.py` — The Orchestrator

This is the script you run. It does **not** do any ML itself. Its job is to:

1. Read `processed_files.txt` to find out which CSV parts have already been trained on
2. For each **new** file, call `train.py <filename>` as a subprocess
3. If the training succeeds, append the filename to `processed_files.txt`
4. If training fails, leave the file unmarked so it gets retried next run

This means you can safely re-run `run_pipeline.py` at any time:
- Already-processed files are skipped instantly
- Only truly new files trigger a training run

To add more data in the future, add the filename to `CSV_PARTS` in `run_pipeline.py`
and drop the file in the project folder — then run the script again.

---

### `train.py` — The ML Pipeline

Called once per CSV file. It runs the full ML pipeline for that batch:

#### Step 1 — Data Preparation (`dataPrep`)

| Action | Reason |
|--------|--------|
| Drop `Name`, `Ticket`, `Cabin` | Too unique / too sparse to be useful features |
| Drop rows with `NaN` | Keeps the data clean without imputation complexity |
| One-hot encode categoricals | Converts `Sex`, `Embarked` etc. to numeric columns |
| 80/20 train-test split | Standard holdout; `random_state=42` for reproducibility |

#### Step 2 — Model Training

A **Random Forest Classifier** (scikit-learn default settings, `random_state=42`)
is trained on the 80% training split.  
Random Forest was chosen because it handles mixed feature types well, is robust
to outliers, and requires minimal tuning to get a reasonable baseline.

#### Step 3 — Evaluation

Accuracy is computed on the 20% test split and logged to MLflow as a metric.

#### Step 4 — Cumulative Predictions

After each run, the test-set predictions are appended to `all_predictions.csv`
with three extra columns:

| Column | What it contains |
|--------|-----------------|
| `Actual` | Ground truth (0 = died, 1 = survived) |
| `Predicted` | Model's prediction |
| `Source_File` | Which CSV part this prediction came from |
| `Run_ID` | The MLflow run ID, so you can trace it back |

This file grows with every run, giving a full history across all batches.

#### Step 5 — MLflow Logging

Each run logs:

| Type | What |
|------|------|
| Tag | `data_version` — which CSV file was used |
| Param | `model`, `new_data_file`, `total_predictions_so_far` |
| Metric | `accuracy` |
| Artifact | Snapshot of `all_predictions.csv` at that point in time |
| Artifact | The trained model (loadable with `mlflow.sklearn.load_model`) |

1.if __name__ == "__main__":
— This condition is only True when you run the file directly (python train.py ...). If another script imports train.py (like run_pipeline.py likely does), this block is skipped entirely, so importing won't accidentally trigger training.
2.if len(sys.argv) < 2:
— Checks that you passed a CSV filename as an argument. sys.argv is the list of command-line arguments, where sys.argv[0] is always the script name itself. If no CSV path is given, it prints usage instructions and exits.
3.new_csv = sys.argv[1]
— Grabs the first argument you passed, e.g. part1.csv.
4.if not os.path.exists(new_csv):
— Validates that the file actually exists on disk before doing anything. Exits with a clear error message if not.
5.train(new_csv)
— Calls the main train() function defined above, which runs the full ML pipeline: data prep → model training → evaluation → MLflow logging.

## Current Results

### Part 1 Run
- Trained on `part1.csv`
- MLflow run logged under experiment **Default**
- `all_predictions.csv` created with predictions from this batch
- `processed_files.txt` created with `part1.csv` recorded

### Part 2 Run
- `run_pipeline.py` detects `part1.csv` is already done (skips it)
- Trains on `part2.csv` only
- Predictions from Part 2 are **appended** to `all_predictions.csv`
- Final CSV contains predictions from both batches, each labelled with their source file and run ID
- Both runs visible side-by-side in the MLflow UI

## How to Run

### 1. Install dependencies

```bash
pip install pandas scikit-learn mlflow
```

### 2. Run the pipeline

```bash
python run_pipeline.py
```

First run: processes `part1.csv` only (since `part2.csv` wasn't listed yet, or vice versa).  
Second run (after adding `part2.csv` to `CSV_PARTS`): skips `part1.csv`, processes `part2.csv`.

### 3. View results in MLflow UI

```bash
mlflow ui
```

Then open [http://localhost:5000](http://localhost:5000) in your browser.  
You will see one run per CSV part, each with its own accuracy metric, parameters,
and a downloadable predictions artifact.

## Key Design Decisions

**Why subprocess instead of importing train.py directly?**  
Each `subprocess.run` call is a fully isolated Python process. This means MLflow
starts and ends a clean run context each time, with no risk of state leaking
between batches.

**Why a flat text file for the processed log?**  
It's human-readable, easy to inspect, and trivial to reset (just delete the file
to re-run everything from scratch).

**Why cumulative predictions?**  
In a real incremental pipeline, you want a single source of truth for all
predictions ever made — not just the latest batch. Appending to one CSV (and
snapshotting it in MLflow) gives you that audit trail.
